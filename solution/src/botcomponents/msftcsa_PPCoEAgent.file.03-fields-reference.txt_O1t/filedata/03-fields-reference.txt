# 03 — Fields reference

This is the **definitive field list** for building `where` and
`orderby` clauses. For every field: what it is, what type it has,
which resource type(s) it lives on, and what operators are sensible.

> 🚨 **Critical:** Filtering on a field that doesn't exist on the
> targeted resource type returns **zero rows silently** — ARG does
> not error. Always check the "Lives on" column. When a question
> implies cross-resource filtering, use the **two-step pattern**
> (see `07-recipes.txt`, recipes 7.11–7.13).
>
> 💡 **Value formatting (from `01-agent-role-and-output.txt`,
> hard rule 2):**
> - Strings → single-quoted inside the JSON: `"Values": ["'foo'"]`
> - Booleans → unquoted: `"Values": ["true"]`
> - Numbers → unquoted: `"Values": ["30"]`
> - `ago(Nd)` and other KQL function calls → unquoted: `"Values": ["ago(30d)"]`
> - `in~` and `has_any` → one quoted string per item:
>   `"Values": ["'Production'", "'Sandbox'"]`

## Top-level (envelope) fields

These have **no `properties.` prefix** and exist on every resource.

| Field | Type | Lives on | Domain | Common ops |
|---|---|---|---|---|
| `type` | string | All 10 | one of the 10 type strings | `==`, `in~` |
| `name` | string (GUID) | All 10 | bare GUID | `==`, `contains` |
| `location` | string | All 10 | lower-case region, e.g. `'unitedstates'`, `'westus'`, `'westeurope'` | `==`, `in~` |
| `tenantId` | string (GUID) | All 10 | one value per tenant | rarely filtered |

`orderby` on top-level fields does **not** need `tostring()`:

```json
{ "$type": "orderby", "FieldNamesAscDesc": { "name": "asc" } }
```

## 🔶 Polymorphic owner / creator fields — READ CAREFULLY

**These three fields are not always GUID strings.** Sometimes the
inventory returns them as an **object** `{ id, displayName, email }`.
A naïve `==` against a GUID will silently miss the object form.

| Field | Lives on | Shapes seen | **Recommended ops** |
|---|---|---|---|
| 🔶 `properties.ownerId` | All apps, all flows, agents (not envs / env groups) | (a) GUID string `'05782d11-...'` (b) object `{id, displayName, email}` | **`contains`** with the GUID — works for both shapes. Avoid `==`. |
| 🔶 `properties.createdBy` | All 10 | same as `ownerId` | **`contains`** with the GUID |
| 🔶 `properties.lastModifiedBy` | All resources except envs / env groups | same as `ownerId`. May also be the empty string for system-managed records. | **`contains`** with the GUID, or skip the filter for system records |

**Filter clause for "owned by user GUID X":**

```json
{
  "$type": "where",
  "FieldName": "properties.ownerId",
  "Operator": "contains",
  "Values": ["'12345678-1234-1234-1234-123456789012'"]
}
```

`contains` translates to KQL `contains` — substring match on the
stringified value — which catches both the bare GUID and the
serialized object (which embeds the GUID under `id`).

## Universal `properties.*` fields

Present on every resource type with the same meaning.

| Field | Type | Domain | Common ops |
|---|---|---|---|
| `properties.displayName` | string | free text | `contains`, `startswith`, `endswith`, `==` |
| `properties.environmentId` | string (GUID) | bare GUID | `==`, `in~` |
| `properties.createdAt` | datetime (ISO 8601) | e.g. `'2026-05-19T17:53:19Z'` | `> ago(Nd)`, `<`, `>` |
| `properties.lastModifiedAt` | datetime (ISO 8601) | same | `> ago(Nd)`, `<`, `>` |
| `properties.isQuarantined` | boolean (unquoted) | `"true"` / `"false"` | `==` |

`orderby` on `properties.*` fields **must** be wrapped in
`tostring()`:

```json
{ "$type": "orderby", "FieldNamesAscDesc": { "tostring(properties.lastModifiedAt)": "desc" } }
```

## Environment fields

> 🚨 **These fields only exist on `microsoft.powerplatform/environments`.**
> They are **NOT** present on apps / flows / agents.

| Field | Type | Domain | Common ops |
|---|---|---|---|
| `properties.environmentType` | string | `'Production'`, `'Default'`, `'Sandbox'`, `'Trial'`, `'Developer'`, `'Dataverse for Teams'` | `==`, `in~` |
| `properties.isManaged` | boolean | `"true"` / `"false"` | `==` (Managed Environments flag) |
| `properties.environmentGroup` | string | env group display name | `==`, `contains` |
| `properties.environmentGroupId` | string (GUID) | env group GUID | `==`, `in~` |

**To filter apps/flows/agents "in environments of type X":** use the
**two-step pattern** (recipes 7.11–7.13). Step 1 finds the env GUIDs;
step 2 filters by `properties.environmentId in~ <guids>`.

## 🚫 What's NOT in the inventory — DO NOT OFFER THESE AS REFINEMENTS

The `PowerPlatformResources` inventory is a **topology and
metadata** table. It tells you what exists, who created/owns it,
when it was modified, what it's wired to. It does **NOT** carry
runtime, telemetry, billing, identity, or licensing data.

When the user asks for any of the below — or when you're tempted to
offer one of them as a "would you like to refine by…" suggestion —
**don't**. Explain plainly that the inventory doesn't carry it and,
where possible, name the system that does.

| Concept the user might ask for | Why it's not here | Where it lives |
|---|---|---|
| **Launch / run COUNT** ("how many times was this used", "top 10 most-used apps", "session count", "DAU / MAU") | The inventory has timestamps, not counts. There is no run count, session count, or DAU/MAU field on any resource. | Power Platform admin analytics, Application Insights (if instrumented), PPAC "Analytics" surface |
| **Active USERS** ("how many people used this app last month") | Topology only — no per-user activity data | Power Platform admin analytics; per-app analytics in maker portal |
| **Last RUN / EXECUTION time for flows** | The inventory has `properties.lastModifiedAt` (edit time) but no separate "last run" timestamp | Power Automate run history (per flow) |
| **Last LAUNCH time for non-canvas apps** | Only canvas apps publish `properties.lastLaunchedTime`. Model-driven / code / app-builder apps do not. | None — model-driven and code apps simply don't expose this |
| **License / capacity / billing data** | Not in the inventory | Power Platform admin center → Billing |
| **User account status** ("disabled", "left the org") | Inventory only stores owner/creator GUIDs | Microsoft Entra ID / Microsoft Graph |
| **User profile fields** (department, manager, title) for owners | The polymorphic shape sometimes embeds display name and email but never department/manager | Microsoft Graph |
| **DLP policy assignments** for a specific app/flow | Not in the inventory rows | Power Platform admin DLP APIs |
| **Sharing details** beyond canvas-app `sharedUsersCount` / `sharedGroupsCount` counts (e.g. WHO the app is shared with) | The inventory only carries the counts | Power Apps admin connector `GetSharedPrincipals` |
| **Connection / credential information** for a flow (which connection ID, which account) | Not in the inventory | Power Platform admin `ListConnections` connector |
| **App PERFORMANCE / latency metrics** | Not in the inventory | Application Insights, Monitor / Tracer |

### ✅ What IS available that LOOKS like usage (use with honest caveats)

These are the few signals the inventory **does** carry that are
adjacent to "usage". They're useful, but be precise about what they
do and don't tell you:

| Signal | What it tells you | What it does NOT tell you |
|---|---|---|
| `properties.lastLaunchedTime` (**canvas apps only**) | The **timestamp** of the most recent launch. Great for "canvas apps not launched in the last 90 days" or "recently-active canvas apps". | How many times it was launched, by whom, or for how long. Not available on model-driven / code / app-builder apps. |
| `properties.lastModifiedAt` (every resource) | When the resource was last **edited**. A weak proxy for "is anyone maintaining this?" | Anything about **usage**. A heavily-used app that no one's edited in a year still shows old `lastModifiedAt`. |
| `properties.sharedUsersCount` / `sharedGroupsCount` (**canvas apps only**) | How many users/groups the app has been **shared with**. A weak proxy for reach. | Whether any of those users actually launch it. |
| `properties.lastPublishedAt` (**agents only**) | When the agent was last **published**. Useful for "agents not republished recently". | How often it's invoked, how many conversations it handles. |

### When the user asks for one of the truly unavailable concepts above, your reply template is:

```
That data isn't in the PowerPlatformResources inventory — it's
[topology only / edit metadata only / etc]. <Name the real source>
holds it. The closest thing I can query for you is <closest
inventory proxy, if any>. Want me to do that instead, or do you
have access to <real source> to provide the data?
```

### When offering "refinement" suggestions after a query, ONLY suggest:

- **Resource type** (narrow / widen the `type` filter)
- **Environment** (specific env GUID, env group, or env type via two-step)
- **Owner / creator** (GUID, polymorphic — use `contains`)
- **Time window** (`> ago(Nd)` for created / modified / last published /
  — for canvas apps only — last launched)
- **Connector usage** — phrase it precisely as **"which connectors
  the resource USES"** (which is what `__connectorBag` queries), not
  as "usage" by itself, which the user might read as runtime usage
- **Name match** (`contains` / `startswith` / `endswith` on displayName)
- **Status / lifecycle flags** (isQuarantined, isManaged, status, flowTriggerType)
- **Sharing breadth** (`sharedUsersCount` / `sharedGroupsCount` on canvas apps)
- **Resource-specific attributes** documented in the per-type tables above

**Never** offer "usage" (ambiguous!), "active users", "run count",
"last run", "license", "performance", "DLP coverage", or
"sharing list" as a refinement — the inventory cannot serve any of
them.

## Fields summary by intent

| User intent | Use this clause |
|---|---|
| "Recently modified" / "in the last N days" | `where properties.lastModifiedAt > ago(Nd)` |
| "Recently created" / "new in the last N days" | `where properties.createdAt > ago(Nd)` |
| "Owned by user X" | 🔶 `where properties.ownerId contains '<GUID>'` |
| "Created by user X" | 🔶 `where properties.createdBy contains '<GUID>'` |
| "Quarantined" | `where properties.isQuarantined == "true"` (apps + agents) |
| "Activated/Suspended/Stopped" (flows) | `where properties.status == '<value>'` |
| "Triggered manually / on-demand" | `where properties.flowTriggerType == 'Instant'` |
| "Uses connector X" | `__connectorBag` sentinel — see `05-sentinel-fields.txt` |
| "Calls operation X" | `__connectorBag` sentinel (it covers operation IDs too) |
| "Managed environments" | `where properties.isManaged == "true"` on environments |
| "In env group X" | `where properties.environmentGroupId == '<GUID>'` |
| "In environment of type X" | **Two-step pattern** — see recipes 7.11–7.13 |
