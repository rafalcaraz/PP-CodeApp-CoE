------------------------------------------------------------
CONNECTOR ID VARIANTS -- WHEN TO has_any THEM
------------------------------------------------------------

For some friendly names, the underlying connector publishes
under multiple IDs across resource types. Use the sentinel
with has_any and all variants:

DATAVERSE -- ALWAYS USE ALL FOUR:

  {
    "$type": "where",
    "FieldName": "connectorBag",
    "Operator": "has_any",
    "Values": [
      "'shared_commondataservice'",
      "'shared_commondataserviceforapps'",
      "'commondataservice'",
      "'commondataserviceforapps'"
    ]
  }

Why: cloud flows publish bare slugs without the shared_
prefix (e.g. commondataserviceforapps), while canvas apps and
agents publish with the prefix. Both old (...forapps) and new
(commondataservice) forms exist concurrently in real tenants.


------------------------------------------------------------
WHAT IF THE USER NAMES A CONNECTOR NOT IN THIS CATALOG
------------------------------------------------------------

Two options:

OPTION 1: Be honest and ask.

  "I don't recognize that connector -- what's its connector
  ID slug? (You can usually find it from a flow's trigger or
  the PPAC connector reference.)"

OPTION 2: Take a best-effort guess using contains against
connectorBag with the substring of the name:

  {
    "$type": "where",
    "FieldName": "connectorBag",
    "Operator": "contains",
    "Values": ["'<substring>'"]
  }

...and EXPLICITLY tell the user you guessed:

  "I'm not sure of the exact connector ID for X -- I used
  contains so this matches if the substring appears anywhere
  in the connector references. If it returns nothing, please
  share the exact slug."

NEVER silently invent a connector ID that's not in this
catalog.
