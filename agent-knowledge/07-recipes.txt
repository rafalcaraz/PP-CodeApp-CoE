============================================================
07 - RECIPES (natural language -> Clauses[])
============================================================

The canonical example library. Each recipe shows a user
question, the JSON the agent should emit, and a one-liner
explanation. All recipes are raw Clauses[] arrays -- paste
them directly into the app's Queries -> Advanced tab and
click Run query.

Conventions:
  - Every recipe starts with a "where type ==" (or
    "where type in~") envelope filter -- never omit it.
  - Order by tostring(properties.lastModifiedAt) desc by
    default; override when the question motivates something
    else.
  - Do NOT emit take -- the user controls page size in the UI.

BASICS
------------------------------------------------------------

7.1 -- "Show me all canvas apps"

[
  {
    "$type": "where",
    "FieldName": "type",
    "Operator": "==",
    "Values": ["'microsoft.powerapps/canvasapps'"]
  },
  {
    "$type": "orderby",
    "FieldNamesAscDesc": { "tostring(properties.lastModifiedAt)": "desc" }
  }

------------------------------------------------------------
CROSS-RESOURCE -- THE TWO-STEP PATTERN
------------------------------------------------------------

These are the most important recipes in this file. They model
how the agent handles questions that CAN'T be answered in one
paste because they need correlation between two resource
types.

Common shape: emit step-1 as a valid Clauses[] array, then
tell the user exactly what to paste back for step 2.


7.11 -- "Apps in Production-type environments"

properties.environmentType lives on environments, not on
apps. Two-step:

STEP 1 -- get the Production env GUIDs:

[
  {
    "$type": "where",
    "FieldName": "type",
    "Operator": "==",
    "Values": ["'microsoft.powerplatform/environments'"]
  },
  {
    "$type": "where",
    "FieldName": "properties.environmentType",
    "Operator": "==",
    "Values": ["'Production'"]
  },
  {
    "$type": "orderby",
    "FieldNamesAscDesc": { "tostring(properties.displayName)": "asc" }
  }
]

Then ask the user: "Paste the resulting name GUIDs back to
me as a comma-separated list and I'll generate step 2 -- the
apps filter."

STEP 2 (template -- needs user-supplied GUIDs):

[
  {
    "$type": "where",
    "FieldName": "type",
    "Operator": "in~",
    "Values": [
      "'microsoft.powerapps/canvasapps'",
      "'microsoft.powerapps/modeldrivenapps'",
      "'microsoft.powerapps/codeapps'",
      "'microsoft.powerapps/apps'"
    ]
  },
  {
    "$type": "where",
    "FieldName": "properties.environmentId",
    "Operator": "in~",
    "Values": ["'<guid1>'", "'<guid2>'"]
  },
  {
    "$type": "orderby",
    "FieldNamesAscDesc": { "tostring(properties.lastModifiedAt)": "desc" }
  }
]

------------------------------------------------------------
TIME-BASED / "ABANDONED" QUERIES
------------------------------------------------------------

7.14 -- "Find abandoned apps" (canonical clock-aware answer)

YOU DO NOT KNOW TODAY'S DATE. Ask the user for the
threshold first. Never invent a date.

THE RIGHT REPLY (no JSON, just a question):

  "Abandoned" needs a threshold. Should I use "not modified
  in the last N days" (you pick N), or "modified before a
  specific ISO date" (you give me the date)?

Once they pick "N days", emit the spec with < ago(<N>d) and
exclude already-quarantined apps:

[
  {
    "$type": "where",
    "FieldName": "type",
    "Operator": "in~",
    "Values": [
      "'microsoft.powerapps/canvasapps'",
      "'microsoft.powerapps/modeldrivenapps'",
      "'microsoft.powerapps/codeapps'",
      "'microsoft.powerapps/apps'"
    ]
  },
  {
    "$type": "where",
    "FieldName": "properties.lastModifiedAt",
    "Operator": "<",
    "Values": ["ago(<N>d)"]
  },
  {
    "$type": "where",
    "FieldName": "properties.isQuarantined",
    "Operator": "==",
    "Values": ["false"]
  },
  {
    "$type": "orderby",
    "FieldNamesAscDesc": { "tostring(properties.lastModifiedAt)": "asc" }
  }
]


7.15 -- "Cloud flows that haven't run in 90 days"

Same shape as 7.14 -- confirm the threshold first, then use
< ago(90d) on properties.lastModifiedAt. (The inventory
doesn't carry a "last run" timestamp distinct from
lastModifiedAt.)

OUT-OF-SCOPE -- NAME THE EXTERNAL SOURCE
------------------------------------------------------------

7.18 -- "Flows owned by users who have left the org"

This requires data the inventory doesn't carry. DON'T emit
JSON.

THE RIGHT REPLY:

  The inventory only stores ownerId as a GUID -- it has no
  field for "account is disabled" or "user has left the
  org". That data lives in Microsoft Entra ID (Azure AD) /
  Microsoft Graph, not in PowerPlatformResources.

  Two ways forward:
    1. Pull disabled / deleted user GUIDs from Microsoft
       Graph (GET /users?$filter=accountEnabled eq false, or
       GET /directory/deletedItems/microsoft.graph.user),
       paste them back, and I'll emit a Clauses[] array
       filtering cloud flows by properties.ownerId in~
       <those GUIDs>.
    2. If you have an existing list of departed-user GUIDs,
       paste them directly and I'll skip step 1.
