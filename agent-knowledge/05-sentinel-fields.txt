============================================================
05 - THE connectorBag SENTINEL PATTERN
============================================================

The single most important pattern in this knowledge pack.
ALWAYS use this for "uses connector X" / "calls operation Y"
intents -- never try to filter properties.powerPlatformConnectors
or properties.connectors directly.

CRITICAL NAMING NOTE: The synthesised column is called
EXACTLY "connectorBag" -- no leading underscores, no
trailing underscores, just the word connectorBag. Spell it
character-by-character: c-o-n-n-e-c-t-o-r-B-a-g. Use it
exactly as shown in every example below.


------------------------------------------------------------
WHY THE PATTERN EXISTS
------------------------------------------------------------

Connector usage is published in THREE different shapes
across resource types, and KQL can't filter dynamic arrays
with ==:

  Shape                                                              Where                                          Slug style
  --------------------------------------------------------------     ---------------------------------------        ------------------------------------------------------
  Array of { connectorId, operations[] } with bare slugs             Canvas apps, flows, agents                     bare slug (sometimes with shared_ prefix, sometimes without)
  Array of { connectorId, connectionType } with ARM path slugs       App-builder apps                               ARM path (/providers/Microsoft.PowerApps/apis/shared_...)
  Nested object                                                      Cloud flow trigger                             bare slug, often empty for first-party connectors

mv-expand isn't in the connector's clause whitelist, so we
can't unwind the arrays. Instead we SYNTHESISE a single
searchable string column that concatenates all three
locations, and run a tokenised has (or has_any) against it.


------------------------------------------------------------
THE PATTERN -- TWO CLAUSES, EVERY TIME
------------------------------------------------------------

You always emit EXACTLY TWO clauses for a connector filter
(in addition to the usual "where type ==" envelope):

CLAUSE 1 -- extend to build connectorBag.

Emit this ONCE per query, even if you have multiple
connector filters. The expression is FIXED -- copy it
verbatim, including the closing parens:

  {
    "$type": "extend",
    "FieldName": "connectorBag",
    "Expression": "strcat(tostring(properties.powerPlatformConnectors),'|',tostring(properties.connectors),'|',tostring(properties.trigger))"
  }

VERIFY YOUR PARENTHESES BEFORE EMITTING. The Expression
opens with strcat( and three tostring( -- that's FOUR opens.
It closes with FOUR closes: ))) at the end of the trigger
section, plus the final ) for strcat. If you drop a close
paren the connector returns "Expected: )".

Count: strcat(  tostring(  )  '|'  tostring(  )  '|'  tostring(  )  )
       1       2          2       3          3       4          4  1


CLAUSE 2 -- where connectorBag has '<slug>'.

  {
    "$type": "where",
    "FieldName": "connectorBag",
    "Operator": "has",
    "Values": ["'shared_sharepointonline'"]
  }


------------------------------------------------------------
OPERATOR TRANSLATION
------------------------------------------------------------

User intent                                              Operator    Values
------------------------------------------------------   ---------   --------------------------------------
uses connector X                                         has         ["'<slug>'"]
does NOT use connector X                                 !has        ["'<slug>'"]
uses any of these connectors (OR)                        has_any     ["'<slug1>'", "'<slug2>'", ...]
substring match (e.g. anything with sharepoint)          contains    ["'<substring>'"]


------------------------------------------------------------
WORKED EXAMPLES
------------------------------------------------------------

CANVAS APPS USING SHAREPOINT:

[
  {
    "$type": "where",
    "FieldName": "type",
    "Operator": "==",
    "Values": ["'microsoft.powerapps/canvasapps'"]
  },
  {
    "$type": "extend",
    "FieldName": "connectorBag",
    "Expression": "strcat(tostring(properties.powerPlatformConnectors),'|',tostring(properties.connectors),'|',tostring(properties.trigger))"
  },
  {
    "$type": "where",
    "FieldName": "connectorBag",
    "Operator": "has",
    "Values": ["'shared_sharepointonline'"]
  },
  {
    "$type": "orderby",
    "FieldNamesAscDesc": { "tostring(properties.lastModifiedAt)": "desc" }
  }
]


FLOWS USING OFFICE 365 OR SQL (OR semantics via has_any):

[
  {
    "$type": "where",
    "FieldName": "type",
    "Operator": "==",
    "Values": ["'microsoft.powerautomate/cloudflows'"]
  },
  {
    "$type": "extend",
    "FieldName": "connectorBag",
    "Expression": "strcat(tostring(properties.powerPlatformConnectors),'|',tostring(properties.connectors),'|',tostring(properties.trigger))"
  },
  {
    "$type": "where",
    "FieldName": "connectorBag",
    "Operator": "has_any",
    "Values": ["'shared_office365'", "'shared_sql'"]
  },
  {
    "$type": "orderby",
    "FieldNamesAscDesc": { "tostring(properties.lastModifiedAt)": "desc" }
  }
]


FLOWS USING BOTH OFFICE 365 AND SQL (AND semantics via two
where clauses):

The extend is emitted ONCE, then two separate
where connectorBag has clauses against the same synthesised
column give AND semantics:

[
  {
    "$type": "where",
    "FieldName": "type",
    "Operator": "==",
    "Values": ["'microsoft.powerautomate/cloudflows'"]
  },
  {
    "$type": "extend",
    "FieldName": "connectorBag",
    "Expression": "strcat(tostring(properties.powerPlatformConnectors),'|',tostring(properties.connectors),'|',tostring(properties.trigger))"
  },
  {
    "$type": "where",
    "FieldName": "connectorBag",
    "Operator": "has",
    "Values": ["'shared_office365'"]
  },
  {
    "$type": "where",
    "FieldName": "connectorBag",
    "Operator": "has",
    "Values": ["'shared_sql'"]
  },
  {
    "$type": "orderby",
    "FieldNamesAscDesc": { "tostring(properties.lastModifiedAt)": "desc" }
  }
]


------------------------------------------------------------
WHEN NOT TO USE THE SENTINEL
------------------------------------------------------------

The sentinel pattern only adds value when filtering on the
connector NAME (slug). If the user wants:

  - The cloud-flow TRIGGER display name -> filter
    properties.trigger.connectorDisplayName directly.
  - The cloud-flow TRIGGER operation -> filter
    properties.trigger.operationId directly.
  - A specific operation ID across resource types -> still
    use the connectorBag sentinel -- the bag includes
    operations[] too, because
    tostring(properties.powerPlatformConnectors) serialises
    the whole connector -> operations array.


------------------------------------------------------------
DATAVERSE NEEDS SPECIAL HANDLING
------------------------------------------------------------

Because cloud flows publish the Dataverse connector under a
slug WITHOUT the shared_ prefix (commondataserviceforapps),
while canvas apps and agents use the prefixed form
(shared_commondataserviceforapps), and an even newer current
slug (commondataservice / shared_commondataservice) is in
play -- ALWAYS has_any across all four variants when the
user asks for Dataverse:

  {
    "$type": "where",
    "FieldName": "connectorBag",
    "Operator": "has_any",
    "Values": [
      "'shared_commondataservice'",
      "'shared_commondataserviceforapps'",
      "'commondataservice'",
      "'commondataserviceforapps'"
    ]
  }
