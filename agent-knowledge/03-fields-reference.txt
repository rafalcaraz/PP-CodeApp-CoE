============================================================
03 - FIELDS REFERENCE
============================================================

The definitive field list for building where and orderby
clauses. For every field: what it is, what type it has, which
resource type(s) it lives on, and what operators are sensible.

CRITICAL: Filtering on a field that doesn't exist on the
targeted resource type returns ZERO rows silently -- ARG does
not error. Always check the "Lives on" column. When a question
implies cross-resource filtering, use the two-step pattern
(see 07-recipes, recipes 7.11 through 7.13).

VALUE FORMATTING (from 01-agent-role-and-output, hard rule 2):
  - Strings: single-quoted inside the JSON.
      "Values": ["'foo'"]
  - Booleans: unquoted.
      "Values": ["true"]
  - Numbers: unquoted.
      "Values": ["30"]
  - ago(Nd) and other KQL function calls: unquoted.
      "Values": ["ago(30d)"]
  - in~ and has_any: one quoted string per item.
      "Values": ["'Production'", "'Sandbox'"]


------------------------------------------------------------
TOP-LEVEL (ENVELOPE) FIELDS
------------------------------------------------------------

These have NO properties. prefix and exist on every resource.

Field        Type            Lives on    Domain                                         Common ops
---------    ------------    --------    ----------------------------------------       ----------------
type         string          All 10      one of the 10 type strings                     ==, in~
name         string (GUID)   All 10      bare GUID                                      ==, contains
location     string          All 10      lower-case region, e.g. 'unitedstates'         ==, in~
tenantId     string (GUID)   All 10      one value per tenant                           rarely filtered

orderby on top-level fields does NOT need tostring():
  { "$type": "orderby", "FieldNamesAscDesc": { "name": "asc" } }


------------------------------------------------------------
POLYMORPHIC OWNER / CREATOR FIELDS -- READ CAREFULLY
------------------------------------------------------------

THESE THREE FIELDS ARE NOT ALWAYS GUID STRINGS. Sometimes
the inventory returns them as an OBJECT { id, displayName,
email }. A naive == against a GUID will silently MISS the
object form.

Field                            Lives on                                              Shapes seen                                                                       Recommended op
----------------------------     -------------------------------                       ----------------------------------------------------------------------            ------------------
properties.ownerId               All apps, all flows, agents (not envs / env groups)   (a) GUID string '05782d11-...' (b) object { id, displayName, email }              contains (avoid ==)
properties.createdBy             All 10                                                same as ownerId                                                                   contains
properties.lastModifiedBy        All except envs / env groups                          same as ownerId. May also be the empty string for system-managed records.        contains, or skip filter

Filter clause for "owned by user GUID X":

  {
    "$type": "where",
    "FieldName": "properties.ownerId",
    "Operator": "contains",
    "Values": ["'12345678-1234-1234-1234-123456789012'"]
  }

contains translates to KQL contains (substring match on the
stringified value), which catches BOTH the bare GUID and the
serialized object (which embeds the GUID under id).

UNIVERSAL properties.* FIELDS
------------------------------------------------------------

Present on every resource type with the same meaning.

Field                          Type                                    Domain                                       Common ops
-----------------------------  ----------------------------------      -------------------------------------        --------------------
properties.displayName         string                                  free text                                    contains, startswith, endswith, ==
properties.environmentId       string (GUID)                           bare GUID                                    ==, in~

------------------------------------------------------------
WHAT IS NOT IN THE INVENTORY -- DO NOT OFFER AS REFINEMENTS
------------------------------------------------------------

The PowerPlatformResources inventory is a TOPOLOGY AND
METADATA table. It tells you what exists, who created/owns
it, when it was modified, what it's wired to. It does NOT
carry runtime, telemetry, billing, identity, or licensing
data.

When the user asks for any of the below -- or when you're
tempted to offer one of them as a "would you like to refine
by..." suggestion -- DON'T. Explain plainly that the
inventory doesn't carry it and, where possible, name the
system that does.

Concept the user might ask for                                                                                          Why it's not here                                                                       Where it lives
------------------------------------------------------------------------------------                                    ----------------------------------------------------------------                        ----------------------------------------------------------------
Launch / run COUNT ("how many times was this used", "most-used apps", "session count", DAU / MAU)                       Inventory has timestamps, NOT counts.                                                   Power Platform admin analytics, App Insights, PPAC "Analytics" surface
Active USERS ("how many people used this app last month")                                                               Topology only -- no per-user activity data                                              PPAC admin analytics, per-app analytics in maker portal
Last RUN / EXECUTION time for flows                                                                                     Inventory has properties.lastModifiedAt (edit time), no separate "last run" timestamp   Power Automate run history (per flow)
Last LAUNCH time for non-canvas apps                                                                                    Only canvas apps publish properties.lastLaunchedTime                                    None -- model-driven and code apps simply do not expose this
License / capacity / billing data                                                                                       Not in the inventory                                                                    Power Platform admin center -> Billing
User account status ("disabled", "left the org")                                                                        Inventory only stores owner/creator GUIDs                                               Microsoft Entra ID / Microsoft Graph
User profile fields (department, manager, title) for owners                                                             Polymorphic shape sometimes embeds displayName/email but never department/manager       Microsoft Graph
DLP policy assignments for a specific app/flow                                                                          Not in the inventory rows                                                               Power Platform admin DLP APIs
Sharing details beyond canvas-app sharedUsersCount / sharedGroupsCount counts (WHO the app is shared with)              Inventory only carries the counts                                                       Power Apps admin connector GetSharedPrincipals
Connection / credential information for a flow (which connection ID, which account)                                     Not in the inventory                                                                    Power Platform admin ListConnections connector
App PERFORMANCE / latency metrics                                                                                       Not in the inventory                                                                    Application Insights, Monitor / Tracer


WHAT IS AVAILABLE THAT LOOKS LIKE USAGE (use with honest caveats):

These few signals the inventory DOES carry are adjacent to
"usage". They're useful but be precise about what they do and
don't tell you:

Signal                                                          What it tells you                                                                                                       What it does NOT tell you
------------------------------------------------------          --------------------------------------------------------------------------------------------------                      ----------------------------------------------------------------------------------------------
properties.lastLaunchedTime (CANVAS APPS ONLY)                  Timestamp of the most recent launch. Great for "canvas apps not launched in 90 days" or "recently-active canvas apps". How many times launched, by whom, or for how long. Not available on model-driven / code / app-builder apps.
properties.lastModifiedAt (every resource)                      When the resource was last EDITED. A weak proxy for "is anyone maintaining this?"                                       Anything about USAGE. A heavily-used app no one's edited still shows old lastModifiedAt.
properties.sharedUsersCount / sharedGroupsCount (CANVAS ONLY)   How many users/groups the app has been SHARED with. A weak proxy for reach.                                              Whether any of those users actually launch it.
properties.lastPublishedAt (AGENTS ONLY)                        When the agent was last PUBLISHED. Useful for "agents not republished recently".                                        How often it's invoked, how many conversations it handles.


WHEN THE USER ASKS FOR AN UNAVAILABLE CONCEPT, your reply
template:

  That data isn't in the PowerPlatformResources inventory --
  it's [topology only / edit metadata only / etc]. <Name the
  real source> holds it. The closest thing I can query for
  you is <closest inventory proxy, if any>. Want me to do
  that instead, or do you have access to <real source> to
  provide the data?


WHEN OFFERING "REFINEMENT" SUGGESTIONS AFTER A QUERY, ONLY
SUGGEST:

  - Resource type (narrow / widen the type filter)
  - Environment (specific env GUID, env group, or env type via two-step)
  - Owner / creator (GUID, polymorphic -- use contains)
  - Time window (> ago(Nd) for created / modified / last published /
    for canvas apps only, last launched)
  - Which connectors a resource USES (phrase precisely; never just
    "usage" by itself, which the user might read as runtime usage)
  - Name match (contains / startswith / endswith on displayName)
  - Status / lifecycle flags (isQuarantined, isManaged, status, flowTriggerType)
  - Sharing breadth (sharedUsersCount / sharedGroupsCount on canvas apps)
  - Resource-specific attributes documented in the per-type tables above

NEVER offer "usage" (ambiguous!), "active users", "run count",
"last run", "license", "performance", "DLP coverage", or
"sharing list" as a refinement -- the inventory cannot serve
any of them.

FIELDS SUMMARY BY INTENT
------------------------------------------------------------

User intent                                                Use this clause
-------------------------------------------------------    -----------------------------------------------------------------------
"Recently modified" / "in the last N days"                 where properties.lastModifiedAt > ago(Nd)
"Recently created" / "new in the last N days"              where properties.createdAt > ago(Nd)
"Owned by user X"                                          where properties.ownerId contains '<GUID>'
"Created by user X"                                        where properties.createdBy contains '<GUID>'
"Quarantined"                                              where properties.isQuarantined == "true" (apps + agents)
"Activated/Suspended/Stopped" (flows)                      where properties.status == '<value>'
"Triggered manually / on-demand"                           where properties.flowTriggerType == 'Instant'
"Uses connector X"                                         connectorBag sentinel -- see 05-sentinel-fields
"Calls operation X"                                        connectorBag sentinel (covers operation IDs too)
"Managed environments"                                     where properties.isManaged == "true" on environments
"In env group X"                                           where properties.environmentGroupId == '<GUID>'
"In environment of type X"                                 TWO-STEP pattern -- see recipes 7.11 through 7.13
